## 文档说明

- 状态：产品方向修订稿，供产品、数据、研发及风险/合规评审
- 版本：v0.2
- 修订依据：针对首版范围、用户与市场边界、评分口径、验收指标、多智能体失败处理和风险边界补充
- 重要假设：首版暂按“面向个人投资者的研究辅助工具”设计；目标市场、证券范围、数据服务商及合规要求尚未确认。以下相关内容均为待确认项，不构成已批准决策。

## 1. 产品目标与边界

帮助个人投资者将筛选目标转化为一组可检查、可解释、可重复生成的候选股票。产品提供信息整理、条件筛选和研究辅助，不代替用户作出投资决策，不接收或执行交易指令，也不承诺收益。

首版成功标准：用户可以选择预设条件，查看筛选结果及其数据依据，理解主要风险，并在数据不可用或分析失败时得到清楚提示。

## 2. 首版范围（MVP）

### 纳入首版

1. **范围与风险偏好设置**：选择支持的市场/股票池，设置投资期限、风险偏好、行业和基础排除条件。提交前展示条件摘要供用户确认。
2. **预设策略筛选**：提供少量经产品和数据团队确认的模板（建议首发 2–3 个，例如价值、成长、质量，最终待数据可用性确认）。每个模板展示适用说明、条件定义和数据日期。
3. **候选列表**：展示名称/代码、行业、满足的筛选条件、关键指标、主要风险提示、数据更新时间及来源。支持按少量明确指标排序；首版不提供不可解释的单一“AI 总分”。
4. **股票简要研究卡**：展示基础资料、筛选相关指标、正反向证据和风险事项；每项关键事实附来源与时间。数据不足时标注未知，不由模型补猜。
5. **条件调整与重新筛选**：用户修改条件后重新运行，并能看到结果变化及对应条件。相同数据快照和条件应产生一致的筛选结果。
6. **安全与失败提示**：披露数据延迟、覆盖范围及筛选限制；数据源不可用、关键字段缺失或分析服务失败时，显示失败/降级状态，不展示未经验证的结论。

### 暂不纳入首版

- 任意自然语言策略自动转成条件并直接运行（后续可先做“生成草稿—用户确认”）。
- 自定义因子、自由组合评分权重、策略回测和收益预测。
- 自动交易、下单建议、个性化买卖时点或目标价。
- 多市场、多语言、社交分享、复杂组合优化及自动推送提醒。

上述项目可进入后续版本评估，不视为首版上线前置条件。

## 3. 核心用户流程

选择市场/股票池 → 选择预设策略并编辑支持的条件 → 查看并确认条件摘要 → 执行筛选 → 浏览候选列表与数据依据/风险 → 查看个股研究卡 → 修改条件并比较变化。

首次执行前应明确显示数据截至时间、股票池范围及策略说明。流程中不暗示结果代表买入推荐。

## 4. 功能需求与验收标准

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F1 | 用户能查看、修改并确认筛选条件 | 执行前展示完整条件摘要；任何生效条件都能在结果页查看；未确认的解析草稿不得触发筛选 |
| F2 | 使用预设策略筛选指定股票池 | 策略模板有版本号、条件定义和适用说明；对相同股票池、数据快照、策略版本及参数重复运行，入选集合与排序规则一致 |
| F3 | 展示结果和依据 | 每个结果包含证券标识、匹配条件、关键指标、数据来源/日期和风险提示；无来源的关键事实不得作为事实呈现 |
| F4 | 解释未入选原因 | 对被用户查看的未入选股票，能指出未满足的可计算条件；字段缺失应说明“无法判断”，不得记作不满足 |
| F5 | 支持数据异常降级 | 关键字段缺失、超出新鲜度阈值或数据服务失败时，按字段/结果标注并依预设规则停止或降级；不得静默沿用过期值 |
| F6 | 呈现风险与信息边界 | 结果页展示风险事项、数据时间、覆盖范围、延迟及非保证说明；不出现自动交易入口或确定性收益承诺 |
| F7 | 多智能体输出可审查 | 用户可见结论关联结构化证据、来源和时间；内部智能体冲突、超时或失败按第 6 节规则处理，并记录状态 |

建议首发上线门槛（具体阈值需由数据与产品负责人根据数据合同和目标市场确认）：

- 关键展示事实的来源及时间覆盖率：100%；无法满足时不呈现该事实或明确标缺失。
- 使用同一数据快照、策略版本和参数复跑：筛选成员及排序完全一致。
- 关键字段新鲜度：由数据负责人按数据类型设定 SLA，并在界面显示实际数据时间；超过 SLA 的数据不得无提示参与筛选。
- 核心流程验收：测试用户能从条件摘要追溯到候选入选依据，能识别至少一个适用限制或风险提示。可用性样本量和通过率在用户测试计划中确定。

## 5. 筛选与评分口径

首版以“条件命中/未命中/无法判断”和可直接查看的指标排序为主，不生成综合 AI 分数或个性化风险等级。这样可以避免在尚未验证权重、历史稳定性和适用范围时制造精确感。

每项筛选条件需在策略说明中定义：指标名称、计算/数据口径、比较运算符、统计区间、币种/单位、数据源、更新时间要求及缺失值规则。未确认口径的指标不进入可执行模板。

若后续版本引入评分，须另行定义并评审：指标标准化方法、方向、权重来源、缺失处理、行业/市场可比性、版本变更记录、敏感性分析及用户可理解的解释；评分不得被描述为收益概率或安全保证。

## 6. 多智能体协作与故障处理

- **需求解析**：将输入转为受支持的结构化条件；无法映射或存在歧义时追问。只生成草稿，不代替用户确认。
- **筛选执行**：由可复现的规则/计算服务执行确定性条件，语言模型不负责心算或补齐缺失财务数据。
- **证据整理**：整理事实及来源、时间，不改变原始数值和单位；模型生成内容与原始数据分开展示。
- **独立风险复核**：检查风险事项、数据过期/缺失和表达是否过度确定。
- **汇总**：按产品规则整合结果。证据冲突时并列呈现冲突及各自来源；关键事实冲突未解决时隐藏该结论或标为待核实，不由汇总智能体自行择一。

故障规则：关键数据服务失败或筛选计算不可验证时，停止生成候选结论并说明原因；非关键研究模块超时可展示已验证的筛选结果，但显著标注研究卡缺项和失败模块。任何降级结果不得省略状态、数据时间和限制。记录策略/提示词版本、数据快照标识、各环节状态及来源引用，具体保存期限与访问权限待安全/合规评审确认。审计记录保留依据和结论，不向用户暴露无关的内部推理文本。

## 7. 风险、数据与合规前置项

正式开发和上线前需确认：

1. 目标用户、目标市场/司法辖区、证券类型及股票池边界。
2. 行情、财报、行业和事件数据的授权范围、展示限制、刷新频率、历史覆盖和质量责任人。
3. 适用的金融监管、投资建议边界、免责声明、用户告知及投诉/纠错流程；由相应专业人员确认，不以本稿替代法律意见。
4. 用户输入、偏好和行为数据的收集目的、最小化范围、保留期限、删除机制及访问控制。
5. 上线监控与处置：数据中断、异常结果、来源撤回、模型版本变化及用户报告错误时的暂停/回滚责任人。

## 8. 多智能体产品架构建议

优先采用“确定性筛选服务 + 智能体证据整理/解释 + 独立风险复核”的组合。首版不要求所有环节必须由多个智能体实现；如果一个模块可由规则或普通服务可靠完成，应优先采用更可复现的实现。智能体之间传递结构化字段（结论、证据、来源、时间、置信/状态、限制），统一由编排层做超时、校验和降级控制。
